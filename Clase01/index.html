1. Tres formas de usar JavaScript en un HTML

Forma 1: Adentro de una etiqueta (inline)

El código JS se escribe directamente en un atributo de una etiqueta HTML, por ejemplo onclick. Sirve para cosas muy chiquitas, pero mezcla HTML con JS y se vuelve difícil de mantener.

<button onclick="alert('Hola desde la forma 1')">Probar</button>

Forma 2: Con la etiqueta <script> dentro del HTML

Escribimos el código entre <script> y </script> en el mismo archivo HTML. Está todo junto, pero si el archivo crece se vuelve largo y no podemos reutilizar el código en otras páginas.

<script>
  console.log("Hola desde la forma 2");
</script>

👉 Este archivo tiene uno en el <head>: mirá el mensaje en la consola.

Forma 3: En otro archivo (script.js) ✅ la recomendada

El código vive en un archivo aparte y lo vinculamos con el atributo src. Se pone al final del <body> para que el HTML ya esté cargado cuando se ejecute el JS.

<script src="script.js"></script>
FormaVentajaDesventaja
1. InlineRápido para probarMezcla HTML y JS, desordenado
2. <script> internoTodo en un archivoNo se reutiliza, archivo largo
3. Archivo externoOrdenado y reutilizableUn archivo más (¡no es problema!)

2. Variables: let, const y var

Una variable es una "caja" con nombre donde guardamos un dato para usarlo después.

let edad = 25;          // puede cambiar
const nombre = "Ana";   // NO puede cambiar
var ciudad = "Rosario"; // forma vieja, evitarla
Palabra¿Se puede reasignar?¿Cuándo usarla?
letSíCuando el valor va a cambiar (contadores, totales)
constNoPor defecto, para todo lo que no cambia
varSíNunca en código nuevo (tiene comportamientos raros)

Reglas para nombres: empiezan con letra, _ o $; no llevan espacios ni acentos; usamos camelCase (precioTotal); y que se entienda qué guardan.

4. Git y GitHub

Git es un programa que guarda el historial de cambios de tu código (como "puntos de guardado"). GitHub es una página web donde subís ese historial para tenerlo en la nube, compartirlo y trabajar en equipo.

Configuración inicial (una sola vez)

git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"

Flujo de trabajo básico

git init                  # 1. Crear un repositorio en la carpeta
git status                # 2. Ver qué archivos cambiaron
git add .                 # 3. Preparar los cambios (staging)
git commit -m "Clase 01"  # 4. Guardar un punto en el historial
git log --oneline         # Ver el historial de commits

Subir a GitHub

  1. Crear un repositorio nuevo en github.com (botón New).
  2. Conectar tu carpeta con ese repositorio y subir:
git remote add origin https://github.com/usuario/mi-repo.git
git branch -M main
git push -u origin main   # la primera vez
git push                  # las siguientes veces

Otros comandos útiles

git clone URL   # Descargar un repositorio existente
git pull        # Traer los últimos cambios de GitHub

Salida

Lo que imprimen los botones aparece acá y también en la consola (F12).
